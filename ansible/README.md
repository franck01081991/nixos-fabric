# Ansible Configuration for NixOS Fabric

This directory contains Ansible playbooks and roles for managing the NixOS fabric nodes.

## Structure

```
ansible/
├── playbooks/              # Main playbooks
│   ├── setup-common.yml    # Common setup for all nodes
│   ├── main.yml             # Main deployment playbook
│   └── verify-fabric.yml    # Fabric verification playbook
│
├── roles/                  # Ansible roles
│   └── common/              # Common role for all nodes
│       ├── tasks/           # Main tasks
│       ├── handlers/        # Handlers
│       ├── templates/       # Jinja2 templates
│       ├── vars/            # Role variables
│       ├── defaults/        # Default variables
│       └── meta/            # Role metadata
│
├── inventory/              # Inventory files (generated by Nix)
│   └── hosts.ini            # Main inventory
│
├── host_vars/              # Host-specific variables (generated by Nix)
│   ├── rtr-noisy.yml        # Noisy router variables
│   └── rtr-sapinet.yml      # Sapinet router variables
│
└── group_vars/             # Group-specific variables (generated by Nix)
    ├── spine.yml            # Spine nodes variables
    └── leaf.yml             # Leaf nodes variables
```

## Usage

### Running playbooks

```bash
# Run common setup on all nodes
ansible-playbook playbooks/setup-common.yml

# Run main deployment
ansible-playbook playbooks/main.yml

# Verify fabric status
ansible-playbook playbooks/verify-fabric.yml
```

### Using the Nix-integrated runner

The recommended way to run Ansible playbooks is through the Nix-integrated runner:

```bash
# Run on all nodes
ansible-playbook-runner

# Run on specific host
ansible-playbook-runner rtr-noisy
```

## Development

### Adding new roles

1. Create a new role directory:
   ```bash
   mkdir -p roles/new_role/{tasks,handlers,templates,vars,defaults,meta}
   ```

2. Add role metadata in `roles/new_role/meta/main.yml`

3. Create tasks in `roles/new_role/tasks/main.yml`

4. Add the role to your playbook

### Best practices

- Use `ansible.builtin` module names for clarity
- Add handlers for services that need restarting
- Use templates for configuration files
- Document variables in `defaults/main.yml`
- Add tags for selective execution

## Integration with Nix

The Ansible configuration is automatically generated by the Nix module:

- Inventory is created from Nix host configurations
- Variables are generated from Nix options
- Ansible configuration is managed by Nix

### Dynamic Templates

The Jinja2 templates have been updated to use dynamic variables instead of hardcoded values. This allows for more flexible and maintainable configurations:

- **WireGuard Templates**: `wireguard.nix.j2`, `wg0.conf.j2`, `wireguard-secrets.j2`
- **FRR Templates**: `frr.nix.j2`

These templates now use variables like `wg_ip_address`, `wg_peers`, `bgp_neighbors`, etc., which are provided by the Ansible tasks.

### Updated Ansible Tasks

The Ansible tasks have been updated to define the dynamic variables required by the templates:

- **WireGuard Tasks**: Updated to set variables like `wg_ip_address`, `wg_peers`, `wireguard_peers`, etc.
- **FRR Tasks**: New role created to set variables like `bgp_as`, `bgp_router_id`, `bgp_neighbors`, etc.

### Testing

New tests have been added to validate the generated configurations:

- `wireguard-config-test.nix`: Validates WireGuard configuration
- `frr-config-test.nix`: Validates FRR configuration
- `wireguard-wg0-test.nix`: Validates WireGuard wg0.conf configuration
- `wireguard-secrets-test.nix`: Validates WireGuard secrets configuration

See `modules/ansible.nix` for the integration details.
