# NixOS Fabric Structure Reference

This document explains the new modular structure of the NixOS fabric repository, designed for better reproducibility, scalability, and maintainability.

## 🎯 Design Goals

1. **Reproducibility**: Minimal host-specific configuration in `default.nix`
2. **Scalability**: Easy to add new hosts with consistent patterns
3. **Maintainability**: Clear separation of concerns between modules
4. **Flexibility**: Override defaults on a per-host basis

## 📂 Directory Structure

```
nixos-fabric/
├── modules/                  # Reusable modules (shared across all hosts)
│   ├── base.nix              # Common base configuration
│   ├── networking.nix        # Network configuration module
│   ├── wireguard.nix         # WireGuard configuration module
│   ├── frr.nix               # FRR (BGP/OSPF) configuration module
│   ├── security.nix          # Security hardening module
│   └── ssh.nix               # SSH configuration module
│
├── hosts/                   # Host-specific configurations
│   ├── <hostname>/           # Per-host directory
│   │   ├── hardware-configuration.nix  # Hardware-specific settings
│   │   ├── base-variables.nix         # Base configuration variables
│   │   ├── variables.nix              # Host-specific variables
│   │   └── default.nix                # Main configuration (minimal)
│   └── ...
│
├── docs/                    # Documentation
│   ├── reference/            # Reference documentation
│   └── deployment/           # Deployment guides
│
└── scripts/                 # Deployment and management scripts
```

## 🔧 Module System

### Base Module (`modules/base.nix`)

Handles common configuration across all hosts:
- Package management
- User creation
- System settings (state version, console keymap)
- Basic services

### Networking Module (`modules/networking.nix`)

Manages all networking aspects:
- Hostname and timezone
- DNS configuration
- Interface configuration (including loopback)
- Default gateways
- IP forwarding

### WireGuard Module (`modules/wireguard.nix`)

Encapsulates WireGuard configuration:
- Interface creation
- Peer management
- Firewall rules for WireGuard
- Key management paths

### FRR Module (`modules/frr.nix`)

Handles routing protocols:
- BGP configuration (neighbors, address families)
- OSPF configuration (areas, networks)
- EVPN/VXLAN support
- Router IDs and AS numbers

### Security Module (`modules/security.nix`)

Centralizes security configuration:
- SSH server settings
- Firewall rules (nftables)
- Fail2ban configuration
- System hardening (sysctl settings)
- Rate limiting

## 🗃️ Host Configuration Pattern

Each host follows this pattern:

### 1. `hardware-configuration.nix`
- **Purpose**: Hardware-specific settings that shouldn't be versioned
- **Content**: Disk layouts, filesystem configurations, hardware-specific drivers
- **Note**: This file is typically generated by `nixos-generate-config`

### 2. `base-variables.nix`
- **Purpose**: Host-specific overrides for base module
- **Content**:
  - Package lists
  - User configurations
  - System settings overrides
  - Console configurations

### 3. `variables.nix`
- **Purpose**: Main host configuration variables
- **Content**:
  - Networking settings (IPs, gateways, DNS)
  - WireGuard configuration (peers, keys, endpoints)
  - FRR settings (BGP neighbors, OSPF areas)
  - Security settings (SSH, firewall, hardening)

### 4. `default.nix`
- **Purpose**: Minimal main configuration
- **Content**:
  - Module imports
  - Host-specific tweaks (kernel parameters, services)
  - Hardware-specific workarounds
  - **Should be as small as possible**

## 🚀 Adding a New Host

### Step 1: Create Host Directory

```bash
mkdir -p hosts/new-host
```

### Step 2: Create Hardware Configuration

On the new host, run:
```bash
sudo nixos-generate-config --show-hardware-config > hosts/new-host/hardware-configuration.nix
```

### Step 3: Create Base Variables

```nix
# hosts/new-host/base-variables.nix
{ ... }:
{
  network-fabric.base = {
    enable = true;
    
    packages = [
      "git"
      "vim"
      "curl"
      "wireguard-tools"
      "frr"
    ];
    
    users = {
      franck = {
        enable = true;
        sshKey = "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... user@host";
      };
    };
    
    system = {
      stateVersion = "25.11";
      console = {
        keyMap = "fr";
      };
    };
  };
}
```

### Step 4: Create Host Variables

```nix
# hosts/new-host/variables.nix
{ ... }:
{
  network-fabric = {
    networking = {
      enable = true;
      hostName = "new-host";
      timeZone = "Europe/Paris";
      
      loopback = {
        enable = true;
        ipv4 = [ { address = "10.254.0.X"; prefixLength = 32; } ];
      };
    };

    wireguard = {
      enable = true;
      interfaceName = "wgtransport";
      listenPort = 51820;
      privateKeyFile = "/etc/wireguard/new-host.key";
      ips = [ "10.255.0.X/24" ];
      
      peers = {
        spine1 = {
          publicKey = "__SPINE1_PUB__";
          endpoint = "spine1.example.com:51820";
          allowedIPs = [ "10.255.0.1/32" "10.254.0.1/32" ];
          persistentKeepalive = 25;
        };
      };
    };

    frr = {
      enable = true;
      
      bgp = {
        enable = true;
        as = 65000;
        routerId = "10.254.0.X";
        
        neighbors = {
          spine1 = {
            ip = "10.254.0.1";
            as = 65000;
            updateSource = "lo";
            ebgpMultihop = 5;
          };
        };
        
        networks = [ "10.254.0.X/32" ];
      };
    };

    security = {
      enable = true;
      
      ssh = {
        enable = true;
        port = 22;
        authorizedKeys = [
          "ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... user@host"
        ];
      };
      
      hardening = {
        enable = true;
      };
    };
  };
}
```

### Step 5: Create Minimal default.nix

```nix
# hosts/new-host/default.nix
{ config, lib, pkgs, ... }:
{
  imports = [
    ./hardware-configuration.nix
    ./base-variables.nix
    ./variables.nix
    ../../modules/base.nix
    ../../modules/networking.nix
    ../../modules/wireguard.nix
    ../../modules/frr.nix
    ../../modules/security.nix
  ];

  # Host-specific kernel parameters
  boot.kernelParams = [
    "lockdown=confidentiality"
    "slab_nomerge"
    "pti=on"
  ];

  # Host-specific services
  services.journald.extraConfig = ''
    Storage=persistent
    Compress=yes
    SystemMaxUse=512M
  '';

  # Host-specific security settings
  security.apparmor.enable = true;
}
```

### Step 6: Add to Flake

```nix
# flake.nix
{
  nixosConfigurations = {
    "new-host" = mkHost { system = "x86_64-linux"; hostname = "new-host"; };
    # ... existing hosts
  };
}
```

## 🎛️ Configuration Overrides

The module system allows for flexible overrides at different levels:

### Level 1: Module Defaults
- Defined in each module
- Apply to all hosts unless overridden

### Level 2: Host Variables
- Defined in `hosts/<host>/variables.nix`
- Override module defaults for specific host

### Level 3: Base Variables
- Defined in `hosts/<host>/base-variables.nix`
- Override base module settings

### Level 4: Host-Specific Tweaks
- Defined in `hosts/<host>/default.nix`
- Final overrides for host-specific requirements

## 🔄 Common Override Patterns

### Changing WireGuard Port

```nix
# In host variables.nix
network-fabric.wireguard.listenPort = 51821;
```

### Adding BGP Neighbor

```nix
# In host variables.nix
network-fabric.frr.bgp.neighbors.new-peer = {
  ip = "10.254.0.100";
  as = 65100;
  updateSource = "lo";
  ebgpMultihop = 5;
};
```

### Custom Security Hardening

```nix
# In host variables.nix
network-fabric.security.hardening.kernel.sysrq = 1;  # Override default
```

## 📋 Best Practices

1. **Keep `default.nix` minimal**: Only include host-specific tweaks that can't be expressed in variables
2. **Use variables for configuration**: All standard settings should go in `variables.nix`
3. **Follow the module pattern**: Each logical component should have its own module
4. **Document overrides**: Comment why you're overriding a default value
5. **Test incrementally**: Add one module at a time and test
6. **Use consistent naming**: Follow existing patterns for peer names, interface names, etc.

## 🔧 Debugging Tips

### Check Module Options

```bash
nix repl
:l <nixpkgs/nixos/lib/eval-config.nix>
config = evalModules { modules = [./modules/wireguard.nix]; } {}
config.options.network-fabric.wireguard
```

### Test Configuration

```bash
nix eval .#nixosConfigurations.new-host.config.networking.hostName
nix build .#nixosConfigurations.new-host.config.system.build.toplevel --no-link
```

### Check Generated Configuration

```bash
sudo nixos-rebuild dry-activate --flake .#new-host
```

## 📚 Module Reference

### Base Module Options

```nix
network-fabric.base = {
  enable = true/false;          # Enable base module
  packages = [ "pkg1" "pkg2" ]; # Package list
  users.franck = {              # User configuration
    enable = true/false;
    sshKey = "public_key";
  };
  system = {                    # System settings
    stateVersion = "version";
    console.keyMap = "keymap";
  };
}
```

### Networking Module Options

```nix
network-fabric.networking = {
  enable = true/false;
  hostName = "hostname";
  timeZone = "timezone";
  nameservers = [ "dns1" "dns2" ];
  defaultGateway = {
    enable = true/false;
    address = "gateway_ip";
    interface = "interface";
  };
  interfaces = { ... };        # Interface configurations
  loopback = { ... };          # Loopback configuration
}
```

### WireGuard Module Options

```nix
network-fabric.wireguard = {
  enable = true/false;
  interfaceName = "wg0";
  listenPort = 51820;
  privateKeyFile = "/path/to/key";
  ips = [ "ip1" "ip2" ];
  peers = {                    # Peer configurations

      publicKey = "pubkey";
      endpoint = "host:port";
      allowedIPs = [ "ip1" "ip2" ];

  };

```

### FRR Module Options


## 🎉 Benefits of This Structure

1. **Consistency**: All hosts follow the same pattern
2. **Reusability**: Modules can be shared across multiple projects
3. **Maintainability**: Changes to common functionality are made in one place
4. **Scalability**: Adding new hosts requires minimal new code
5. **Clarity**: Separation of concerns makes configuration easier to understand
6. **Testability**: Modules can be tested independently

This structure makes the repository much more maintainable and scalable while keeping host-specific configuration to a minimum.
